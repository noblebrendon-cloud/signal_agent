# Reflective Pressure Spine Architecture

## Scope

The Reflective Pressure Spine v0.2 is an internal local subsystem under `app/reflective_pressure/`. It captures manually provided inputs, classifies pressure with deterministic heuristics, generates template-based reflective drafts, records manual observations, accepts append-only human corrections, preserves golden examples, exports local prompt packs, summarizes ledger state, and reconciles invariants.

## Module Layout

- `taxonomy.py`: allowed values and fail-closed taxonomy validation.
- `models.py`: strict record builders, ID functions, safety flag checks, numeric checks, and record validators.
- `store.py`: append-only JSONL ledger writes and read helpers.
- `classify.py`: deterministic v0 pressure classifier.
- `generate.py`: deterministic v0 draft templates.
- `observe.py`: manual observation append helper.
- `summary.py`: deterministic read-only summaries.
- `reconcile.py`: read-only ledger integrity report.
- `importer.py`: local JSONL seed import with optional classification and draft generation.
- `review.py`: connected review packets for operator workbench use.
- `export.py`: local prompt-pack markdown export under `data/outputs/reflective_pressure/`.
- `cli.py`: operator command surface.

## State Contract

All runtime state is append-only JSONL under `data/state/`. The store uses `app.retention.jsonl_store.append_record`, which applies the repository's existing lock-protected append pattern and hash-chain fields:

- `recorded_at`
- `prev_hash`
- `record_hash`

No command mutates or deletes existing records. Reconciliation verifies record hashes, previous-hash continuity, references, taxonomy fields, safety flags, and numeric bounds.

## Record Flow

### Input

`ReflectivePressureInput` records the manually captured source material. The source can be a social post, comment, screenshot transcription, personal note, article excerpt, group discussion, or other local source. No external source is fetched.

### Classification

`ReflectivePressureClassification` references an existing input. The v0 classifier uses simple keyword rules for theological language, humor-as-shield, moral contradiction, peace-vs-escalation, authority confusion, recognition deprivation, shallow certainty, and unknown.

### Draft

`ReflectivePressureDraft` references an existing input and classification. Drafts are generated by templates for:

- `short_post`
- `reply`
- `pressure_log_entry`
- `letter_of_light_seed`
- `theological_reflection`
- `system_note`

Drafts default to `human_approved: false` and `published: false`.

### Observation

`ReflectivePressureObservation` references an existing input and draft. Metrics are manual only. They include views, reactions, comments, shares, saves, profile clicks, recognition events, constructive reply ratio, self-insertion density, delayed recirculation, and contradiction heat.

### Correction

`ReflectivePressureCorrection` references an existing input and a target input, classification, draft, or observation record. It stores the human-corrected pressure type, surface claim, hidden pressure, scores, recommended output type, reason, and operator label. It never mutates the original record.

### Golden Example

`ReflectivePressureGoldenExample` references an input and classification, with optional correction and draft references. It records why the example matters, the reusable pattern, voice notes, risk notes, and whether it is approved for local prompt-pack export.

## Safety Invariants

- External action is never allowed by this module.
- Irreversible action is never allowed by this module.
- Draft generation is not publication.
- Observation recording is not platform collection.
- Summary is read-only.
- Reconciliation is read-only.
- Corrections are append-only.
- Golden examples are append-only.
- Prompt-pack export writes only under `data/outputs/reflective_pressure/`.
- Missing ledgers are acceptable before any data exists.
- Malformed ledgers fail closed.

## Upgrade Boundary

Future model/provider upgrades should enter behind the existing classification and generation functions only after a separate admission decision. Until then, v0 remains deterministic and local.
